Flujo determinista o IA: por qué la respuesta correcta es las dos

Un flujo determinista hace siempre lo mismo. Un modelo decide. Elegir uno solo deja el sistema cojo: el flujo no entiende variaciones y el modelo no garantiza cumplimiento. La arquitectura honesta los combina.

Publicado el 20 de octubre de 2026 · 3 min de lectura

En este artículo

  1. El flujo manda en lo que no se negocia
  2. El modelo manda en lo que se escribe distinto cada vez
  3. El patrón que funciona
  4. Cómo se ve en un caso real

El flujo manda en lo que no se negocia

Registrar un pedido, calcular un total, enviar un recordatorio, cancelar una cita. Ahí no se quiere creatividad: se quiere que ocurra exactamente igual mil veces. Un modelo en ese punto es un riesgo sin beneficio.

El modelo manda en lo que se escribe distinto cada vez

Entender qué quiere la persona, resumir un caso largo, detectar el tono, redactar una respuesta con contexto. Ahí un flujo rígido fracasa porque la gente no habla en opciones.

El patrón que funciona

Un flujo decide el camino y el modelo aporta la conversación dentro de ese camino. El modelo nunca inventa un dato: consulta una herramienta. El flujo nunca improvisa: ejecuta lo que corresponde.

Cómo se ve en un caso real

Agendar una cita: el flujo define los pasos (identificar, consultar, ofrecer, confirmar, registrar), y el modelo conversa en cada paso. Si la persona cambia de idea a mitad, el modelo lo entiende y el flujo vuelve al paso anterior sin perder lo ya capturado.

Preguntas frecuentes

¿Un flujo con IA es más caro de mantener?

Cuesta más diseñarlo y menos ajustarlo. Un flujo con veinte ramas se vuelve imposible de mantener; uno con un modelo en el centro se ajusta cambiando instrucciones.

¿Cómo se evita que el modelo se salga del flujo?

Con reglas explícitas, herramientas acotadas y validación del lado del servidor. El modelo propone; el sistema verifica.
